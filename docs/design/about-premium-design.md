# About page refinement concept

Status: proposed visual design for owner review. Native app not modified.

Use the approved logo as a single lockup so the mark, wordmark and byline keep
their designed alignment. Place the content on one shared left edge inside a
centered, capped-width column. Keep the existing settings sidebar visual language.
Remove the enclosing card and its segmented cells; use two fine dividers and
three aligned information rows instead. Version appears once in the page body,
with the existing update status aligned to the right. Platform and architecture
share a row, with architecture secondary. Preserve the existing three actions;
View on GitHub is the primary action. Keep copy-build behavior and error feedback.

The screenshot shows 0.28.2 and an up-to-date state because those were present in
the supplied reference; this proof does not check the running app or releases.

Narrow layout: use the available width after settings navigation, scale the logo
proportionally, wrap supporting copy, put update state below the version value
and architecture below macOS, and stack the buttons before they crowd. Use theme
colors and the light logo variant in light themes. Retain the accessible Kaze
name and all current build information when implementing the outlined lockup.

This concept extends the full branding plan; implementation awaits approval.
