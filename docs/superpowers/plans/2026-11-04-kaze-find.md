# Find in the Terminal and Docked Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship issue #155: **Ctrl+Shift+F** (Cmd+F on macOS) opens a small find bar at the top right of the pane that has the keyboard (the session terminal, or the shown docked member tab), searches the whole scrollback, tints every match, marks them on the pane's right edge, and steps through them with Enter / Shift+Enter, without costing anything while it is closed.

**Architecture:** Three lanes in separate worktrees off `feat/find`, with no shared code file. **Lane S** (search) adds `internal/find`, a pure package over `internal/screen` only: a case-folded streaming matcher (KMP over cell runes, wide characters and soft wraps handled, a hard line end resets it), a resumable scan of history plus the live grid with a per-call cell budget, and an incremental refresh after new output. Matches are kept in **stable line numbers** (`screen.Evicted()` plus the absolute row), so the scrollback ring dropping lines off the top never moves a match: a line's number never changes, and a match whose line was evicted is simply dropped. **Lane R** (render) adds three palette tokens (`Match`, `MatchCur`, `MatchMark`) in all five themes, a `render.Marks` input the renderer turns into a per-cell highlight layer next to the selection layer (same snapshot, same cell diff, so only changed cells are drawn again), and `Renderer.DrawScrollMarks`, the right-edge marks recorded once per change into a cached macro. **Lane U** (UI) adds the `find` action and `[keys]` name, the find bar (a `widget.Editor` with the board search field's key handling), keyboard focus between the bar and the pane, and `findWork`, the per-frame glue that runs the search only while the bar is open, turns matches into `render.Marks`, keeps the current match by its position, scrolls to it and restores the view on Esc. A final task updates README, the lander, HANDOFF and the audit.

**Tech Stack:** Go 1.27, Gio v0.10.3 (`widget.Editor`, `gpu/headless` for opt-in captures, `io/semantic`), existing `internal/screen`, `internal/term`, `internal/render`, `internal/theme`, `render.Readable`.

**Inputs:** issue #155 (body), the approved mockup `docs/design/find-mockup.html` (committed on `feat/find`). On behaviour the issue wins; on look the mockup wins. Mockup values used below: bar 34 dp high, radius 10 dp, `top: 8dp; right: 18dp`, padding `0 4 0 10` dp, gap 4 dp; field 220 dp wide, 12.5 sp mono; count `min-width 64dp`, 11.5 sp mono; buttons 26×26 dp, radius 6 dp; separator 1×18 dp; marks 6 dp wide, 2 dp tall (current 3 dp), `right: 3dp`, view band 8 dp wide at 7 % white; Midnight `--hit #3d3566`, `--hitfg #f2efff`, `--cur #f2b84b`, `--curfg #1a1405`, mark `#5a4fb0`.

**Cross-lane contracts (fixed here; nobody renames them):**

Lane S produces, in `internal/find` (imports `internal/screen` and the standard library only):

```go
const MaxMatches = 1000       // matches kept, the newest (nearest the live screen) win
const MaxNeedle  = 256        // runes of the query that count
const StepBudget = 2_000_000  // cells one Step may read (about 4 ms on the owner's laptop, measured in S4)

type Pos   struct{ Line, Col int }        // Line = screen.Evicted() + absolute row (history first)
type Match struct{ Start, End Pos }       // End is the last cell, inclusive (the right half of a wide char)
type Span  struct{ Line, From, To, Match int } // one match's cells on one row, To inclusive

type Search struct{ /* unexported; zero value ready */ }
func (s *Search) SetQuery(text string, matchCase bool) bool // true when the needle changed; restarts the scan
func (s *Search) Output(scr *screen.Screen)                 // under the session lock: output arrived since the last call
func (s *Search) Step(scr *screen.Screen, budget int) bool  // under the lock; true when settled (nothing left to scan)
func (s *Search) Matches() []Match  // sorted, reused: valid until the next Output or Step
func (s *Search) Spans() []Span     // sorted by Line, From; a match across a soft wrap has one span per row
func (s *Search) Capped() bool      // more than MaxMatches were found
func (s *Search) Gen() uint64       // bumps whenever Matches changes
func (s *Search) Nearest(top, bottom int) int // index for "the match nearest the view [top, bottom]", -1 none (Ruling 11)
func (s *Search) Locate(p Pos) int            // the match starting at p, else the first after p, else the last; -1 none
func (s *Search) Scanned() int                // cells read since the zero value (tests and the bench)
```

Lane R produces, in `internal/render`:

```go
// Palette gains: Match, MatchCur, MatchMark color.NRGBA
type MatchSpan struct{ Line, From, To int; Match int32 } // Line is a stable line, as find.Span
type Marks struct {

	Cur   int32       // the current match's index; -1 none

func (r *Renderer) DrawScrollMarks(gtx layout.Context, track image.Rectangle) // after Layout, outside the grid clip
```

## Review Focus

1. **Positions survive the ring.** Matches are in stable lines; eviction, ED 3 and a full ring drop only matches whose lines left, and the current match keeps pointing at the same text while output streams. (S3 `TestEvictionDropsOnlyOldMatches`, `TestClearScrollbackDropsHistoryMatches`; U4 `TestFindCurrentStaysWhileOutputStreams`.)
2. **Nothing while closed, nothing on a still frame.** Closed: zero cells scanned, no `SetMarks`, no marks over any number of output frames. Open and unchanged: `findWork.tick`, the highlight snapshot and `DrawScrollMarks` allocate 0 and take no lock for find. (U4 `TestFindClosedScansNothing`, `TestFindStillFrameAllocatesNothing`; R2 `TestMarksStillFrameAllocatesNothing`; R3 `TestScrollMarksCached`.)
3. **Bounded scans:** one `Step` reads at most its budget; the matches never exceed 1,000; a 100,000-line history settles over several frames without holding the lock for more than one budget. (S2 `TestStepRespectsBudget`, `TestCapKeepsNewest`; S4 benchmarks.)
4. **Output never jumps the view.** Only Enter, Shift+Enter, the arrows, the buttons, a change of the text or Aa scroll the view; new output never does, and Esc returns to where the view was when the bar opened. (U4 `TestFindOutputDoesNotScroll`, `TestFindEscRestoresView`.)
5. **Keyboard ownership:** while the bar has the keyboard the PTY receives nothing; a click in the terminal gives it back and typing reaches the shell; plain Ctrl+F always reaches the shell. (U1 `TestPlainCtrlFGoesToShell`; U3 `TestFindTypingNeverReachesShell`, `TestClickTerminalTakesKeysBack`.)
6. **Readable in every theme:** match and current-match text at least 4.5:1, marks at least 3:1, bar text at least 4.5:1. (R1, U5.)

### Task S2 (Lane S): Scan history and the screen, resumable and capped

**Files:**
- Create: `internal/find/scan.go`, `internal/find/scan_test.go`, `internal/find/testutil_test.go`

**Interfaces:**
- Produces: `Search` with `SetQuery`, `Step`, `Matches`, `Spans`, `Capped`, `Gen`, `Scanned` (contract above), plus:
  - State: `nd needle; m matcher; ring [MaxMatches]Match; head, count int; out []Match /* linearised, cap MaxMatches, made once */; spans []Span /* cap 2*MaxMatches, made once, grows only for matches over more than two rows */; next int /* stable line the scan resumes at */; col int; settled bool; liveFrom int /* stable line of live row 0 at the last full pass */; alt bool; cols, rows int; gen uint64; scanned int`.
  - The rows a scan walks, in stable lines: main screen: `[scr.Evicted(), scr.Evicted()+ScrollbackLen()+rows)`, history through `ScrollbackLine(i)` (its stored cells; past them blank) and the live grid through `Cell(col, row)`; **on the alt screen only the grid**, `[Evicted()+ScrollbackLen(), ...+rows)` (Ruling 6).
  - Cells fed per row (Ruling 5): every cell with `Width != 0` in order (a continuation half is skipped, its lead's `End.Col = col+1`); `Rune == 0` reads as a space; a hard-ended row stops at its last cell that is not a default blank (`screen.Cell{Rune: ' ', Width: 1, FG/BG default}` as `blankCell`, compared by value); a row whose last cell has `screen.AttrWrapped` is fed in full and the matcher **keeps its state** into the next row, except the one blank cell `Print` leaves at the right edge when a wide character did not fit (last cell `' '`, wrapped, and the next row's first cell `Width == 2`), which is skipped. Any other row end calls `m.reset()`.
  - `Step(scr, budget)`: resumes at `next`, reads rows until the budget is spent (the budget counts cells read; a row is never split, so one step may pass its budget by at most one row), clamps `next` up to `scr.Evicted()` first (lines evicted since the last step are gone), and on reaching the end sets `settled`, `liveFrom = Evicted()+ScrollbackLen()`, `cols, rows, alt` as scanned. Returns `settled`. Settled → returns true at once, reading nothing.
  - Each match goes into the ring; past `MaxMatches` the oldest is overwritten and `Capped()` is true (Ruling 9). `Matches()` linearises into `out` only when `gen` changed since the last linearise. `Spans()` splits matches over rows (a wrapped row's span ends at its last fed cell) and is rebuilt with `out`.
  - `SetQuery` with a changed needle: clears matches, `next = 0` (clamped at the next step), `settled = false`, `gen++`.

### Task S3 (Lane S): New output, eviction and picking the current match

**Files:**
- Create: `internal/find/refresh.go`, `internal/find/refresh_test.go`

**Interfaces:**
- Produces: `Output`, `Nearest`, `Locate` (contract above):
  - `Output(scr)`: no-op while the needle is empty. Drops matches with `End.Line < scr.Evicted()` (gone off the top, `gen++` if any). Then:
    - alt switched, or `Size()` changed, or the scan never settled → a full restart (`next = 0`), keeping nothing it cannot prove unchanged (Ruling 8).
    - else the history below `liveFrom` never changes in place (the rule `tabSel.hash` already relies on), so only the live rows and the rows scrolled into history since are scanned again: `from = liveFrom - back`, where `back` covers a needle reaching back over soft wraps (`back = (nd.n + cols - 1) / cols`, at least 1); matches with `End.Line >= from` are dropped; the matcher resets; `next = from`, `settled = false`. The next `Step` finishes it (a few thousand cells: one step).
  - `Nearest(top, bottom)` (stable lines of the view's first and last rows): the first match with `Start.Line` in `[top, bottom]`; else the last match above `top`; else the first below `bottom`; -1 with no matches (Ruling 11). Binary search over the sorted matches, no allocation.

## Rulings made while planning

Each is cheap to overturn in its own task.

1. **A new package, `internal/find`,** pure Go over `internal/screen` only (no `render`, no `term`), so it is tested without a window or a PTY and builds on every OS. `internal/screen` itself gains nothing. (S1 to S3)
2. **Stable line numbers:** a match's line is `screen.Evicted()` plus its absolute row, a number that never changes while the line exists. Eviction, a full ring and ED 3 only drop matches; nothing is shifted, so the current match keeps pointing at its text. The renderer converts back with the same `Evicted()` under the same lock. (S2, S3, R2, U4)
3. **Case:** insensitive by default with `unicode.ToLower` on both sides, rune by rune (no full Unicode case folding: "ß" does not find "SS"). Aa switches to exact. No regex in this version. (S1)
4. **Matches do not overlap** and are found left to right ("aa" in "aaaa" is 2). (S1)
5. **What text is:** cells in order, a wide character once (its right half skipped), a null cell as a space, a row's trailing default blanks are not text, a soft-wrapped row runs on into the next (so a match can span the wrap, skipping the pad blank a wide character leaves at the edge), a hard line end breaks any match. (S2)
6. **Alt screen:** a full-screen app's screen is searched alone; history is not, because it cannot be scrolled to there. Switching screens restarts the search. (S2, S3)
7. **Bounded steps, no goroutine:** a scan reads at most `StepBudget` cells (2,000,000, lowered in S4 if one step takes over 5 ms) per frame under the session lock, then asks for another frame. The default 10,000-line history settles in one frame; a 100,000-line one over a few. No background goroutine, so no extra locking or copying. (S2, S4, U4)
8. **New output rescans only what can change:** history never changes in place, so only the live rows, the lines scrolled into history since, and the rows a needle could reach back across wraps are read again, at most once per frame (coalesced by `OutputSeq`). A resize or an alt switch rescans everything. (S3, U4)
9. **1,000 matches, the newest kept:** past 1,000 the oldest matches (furthest from the live screen) are dropped and the count reads "N of 1000+". Terminal searches are mostly about recent output; the marks then cover the recent part. (S2, U5)
10. **Typing goes to the bar while it has the keyboard;** a click in the terminal gives the keyboard back and leaves the bar open with its highlights; a click in the field takes it again; Esc in the terminal goes to the shell. (U3)
11. **Current match:** on open and on a change of the text or Aa, the first match in view, else the nearest above the view, else the first below (in a terminal you are usually looking for something earlier). The view scrolls only for a text or Aa change, Enter / Shift+Enter / arrows and the buttons, centring the match; new output never scrolls it, and the current match stays the one at the same position (or the next one after it when its text is gone). Next and previous wrap around. (S3, U4)
12. **Where find opens:** the session terminal or the shown member tab, whichever has the keyboard (keys pressed while the agent panel has it fall back to the session, as today, so find opens there). Settings, the board, the doc reader and the empty window: the shortcut does nothing (the agent panel and reader come later, as the issue says). (U2)
13. **One bar at a time:** the text and Aa are window-wide and kept for the life of the window (not saved to `config.toml`, not restored after a restart). The shortcut on the other pane moves the bar there without restoring the old pane's view. The bar closes, without restoring, when its pane stops being shown (session switch, tab closed, member hidden, settings, board or a doc in front). (U2)
14. **Scroll marks** sit in the grid's right margin (the existing 8 dp padding), 6 dp wide, the length of the grid, scaled to every line held (history plus screen); one mark per pixel row, the current one brighter and drawn last, and a faint band for the visible part, as the mockup. They take no clicks in this version. (R3, U4)
15. **Cached marks:** recorded into the renderer's own `op.Ops` once per change and replayed, so a still frame allocates nothing. (R3)
16. **Precedence in a cell:** selection over current match over match over the cell's own colours; text on a match goes through the renderer's `readableCached`, so it is at least 4.5:1 whatever colour the program printed. (R2)
17. **Copy and paste in the bar:** Ctrl+V / Cmd+V paste into the field; copy copies the field's selected text when it has one, else the terminal selection of the pane the bar is on, so "select in the terminal, copy" still works with the bar open. (U3)
18. **Theme tokens** are three new `render.Palette` fields, because the grid is drawn from the palette, not the chrome: Midnight from the mockup (the mark nudged to `#6457c0` for 3:1); the other four picked to the same pattern and fixed by the R1 tests. (R1)
19. **No new `[colors]` keys;** a palette without the tokens falls back to `Selection` and `Cursor`. Cheap to add `match` and `match_current` later. (R1)
20. **The bar reuses chrome tokens** (`ToastBG`, `ToastLine`, `ToastFG`, `ToastGo`, `Muted`, `CapGlyph`, `CapHover`, `Accent`, `DiffDelFG` for "No results") instead of adding bar tokens to five themes; no drop shadow (Gio has no cheap blur; the border carries the edge). (U5)
21. **Placement:** top right of the pane, 8 dp down and 18 dp in, under the workspace banner when one shows; in a narrow pane the field shrinks to 96 dp, then the count hides, then only the field and × remain. (U5)
22. **Keys left out of this version:** F3 / Shift+F3 and Cmd+G / Cmd+Shift+G. Enter and the arrows cover stepping; cheap to add later. (U3)
23. **Accessibility:** the field is labelled "Find" and the count text is its own semantic label, the status a screen reader reads. (U5)
24. **Nothing in bench mode changes:** `KAZE_BENCH` never opens find, and with the bar closed the renderer's only extra work is one nil check, so bench numbers stay comparable. (R2, U4)
25. **Lanes share no file** and Lane U's first three tasks need neither S nor R, so all three lanes start at once; merge order S, R, U puts the lane that consumes both APIs last. (all)
